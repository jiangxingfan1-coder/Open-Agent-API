## 0.0.67 (2026-11-16)

- Add Usage & Quotas using OAA's existing design system, separating gateway token accounting, local key allowances, upstream quota snapshots and local token history.
- Integrate CodexBar quota/cache JSON and ccusage offline daily JSON as optional collectors, with MIT notices and source attribution. No third-party UI is embedded.
- Deduplicate settled delegated usage, preserve unknown/partial counts, distinguish synthetic quota placeholders from measured zero, and age quota, budget and balance observations independently.
- Protect local account monitoring with owner-only loopback access, explicit collection consent, revision checks, bounded processes, and sanitized aggregate output. Local-history scans remain disabled by default.

## 0.0.66 (2026-11-16)

- Discover native/ACP model catalogs instead of fixed model lists, with explicit discovery errors, bounded catalogs and stable route identities.
- Add publication access policies, per-key connection defaults, durable bounded orchestration and private project-workspace bindings. Unsupported tool-isolation modes are refused rather than silently downgraded.
- Add Local Connections for DSH: detected-client and connection cards, scoped keys, model synchronization, metadata-only checks, conflict-aware removal and crash recovery. Existing providers and the separate API-key workflow remain unchanged.
- Harden Codex/Antigravity protocol handling and update agent/model brand assets.
- Fix type-alias default semantics, bound compiler expansions, handle prototype-named orchestration stages, and preserve client-configuration annotations. Special configuration files cannot block file inspection.
- Refresh vulnerable dependency resolutions while preserving the sandbox runtime's supported Zod v3 API. Add `--no-install` for staging local desktop packages before installation.

Native client-only isolation and enforced tool-free planning are not available for every external engine. Catalog discovery and connection checks do not prove generation entitlement. See the capability documentation for each engine's limits.

## 0.0.65 (2026-11-14)

This version makes the gateway installable in more places and checks it against more clients, and it lets a request carry more than text. It installs on Linux (a tar.gz with its own Node.js, and `install.sh`), in Docker and from an npm tarball, runs on Node 24 and 26, and its full test suite passes on Windows in CI. A compatibility lab runs the official Python and Node SDKs and several frameworks against the gateway and replays the requests of a dozen chat clients, and the gateway was changed wherever that found an incompatibility. Callers can send images and ask for JSON that is guaranteed to fit a schema, run events can be pushed to your own endpoint, and approvals can be handled from the command line. A security review led to a set of fixes. One command (`oaa connect <preset>`) now gives the built-in agent a model from a local service or a hosted provider, and a long soak run found and fixed memory and database growth, with a way to prune old data. Several defaults changed on purpose; they are listed under "Behavior changes", with how to get the old behavior back where there is a way. What has not been verified is listed under "Not yet verified".

File names, commands and settings below are those of the repository; the documents they refer to are under `docs/`.

### Behavior changes

- **Caller tools default to `auto`.** A request that carries `tools` and chooses no mode used to be handled as `managed` on the compatibility endpoints, Claude Messages and Gemini (the agent finishes with its own tools, and the response says `X-OAA-Client-Tools: ignored`), and was refused with 400 `unsupported_parameter` on OpenAI's default endpoints (`/v1/chat/completions`, `/v1/responses`). Now the default is `auto`: when the agent can take the tools over (a built-in kernel agent, or an ACP agent whose execution machine declared `client-tools-v1`), they are bridged. The agent's calls come back as `tool_calls` (or the equivalent in the protocol), the caller runs them, and the same task continues; the response carries `X-OAA-Client-Tools: bridge`. Every other agent (Codex, Claude Code, Antigravity, A2A, HTTP adapters) behaves exactly as before on every entry. To get the old handling for all agents, send `X-OAA-Client-Tools: managed`, or set `clientTools.default` to `managed`. One difference remains: with `managed` as the default, OpenAI's default endpoints ignore the tools instead of refusing them, as only `/v1/compat` did before. A forced `tool_choice` is never bridged.
- **A requested JSON format is now enforced.** `response_format` (`json_object`, `json_schema`), Responses `text.format`, Gemini `responseMimeType` with `responseSchema`, and Claude `output_config.format` used to be refused on OpenAI's default endpoints, or passed to the agent as a wish that was never checked. Now a successful response is JSON that parses and fits the schema. A wrong answer is sent back to the agent for correction up to `structuredOutput.maxRepairs` times (0 to 3, default 1), and then the run fails with `structured_output_invalid` (422). Streams are held until the answer has been checked and then sent in one piece. There is no switch for the old pass-through: stop sending the format, or set `structuredOutput.maxRepairs` to `0` to fail at the first wrong answer.
- **Parameters that only influence sampling no longer fail on OpenAI's default endpoints.** `top_k`, `min_p`, `repeat_penalty`, `logit_bias`, a `stop` list of any length and similar vendor knobs are accepted and ignored, and the names that were ignored are listed in the response header `X-OAA-Ignored-Params`. Parameters that change what the gateway has to do (a forced `tool_choice`, `logprobs: true`, `n` above 1, unknown fields) are still refused.
- **Responses and Gemini streams now carry run progress.** A streaming call on `/v1/responses` or the Gemini entry used to contain only the answer. It now also carries one short line per phase of the run (queued, started, a tool called, waiting for an approval, a correction round and so on), in the protocol's own thinking shape: a `reasoning` output item (placed first, so later `output_index` values are one higher) on Responses, parts marked `"thought": true` on Gemini. The answer text, the non-streaming responses and the usage counts are unchanged, and a client that ignores thinking sees the same answer. Chat Completions and Claude Messages stay as they were (off). To turn it off for one request, send `X-OAA-Progress: off` (or `metadata: {"oaa.progress": "off"}`); to turn it off for the gateway, set `streamProgress.responses` and `streamProgress.gemini` to `"off"`; to turn it on for Chat or Claude, set `streamProgress.chat` or `streamProgress.claude` to `"reasoning"`. Code that reads `response.output[0]` of a streamed `response.completed` event gets the reasoning item; read `output_text` instead. See `docs/progress.md`.
- **Images are accepted.** An image part used to be refused with 400 `unsupported_content` on every entry. It is now accepted for agents that can use images; an agent that cannot still refuses it before a run exists. Nothing is fetched from a remote URL unless `images.fetchRemote` is turned on.
- **Developer-platform billing no longer overdraws.** The per-task price is now held when a task starts and released if the task does not complete. Before, it was taken at the end, so concurrent calls could all pass the balance check and push the balance below zero. The per-token part of a charge now stops at a zero balance instead of taking it negative. A balance that was already negative is not pushed further down. There is no switch for the old behavior.
- **A per-token price is refused for an agent that reports no token usage** (`usage_pricing_unsupported`, 400): such an agent can only be priced per task. A listing saved earlier keeps its price.
- **Agent-limited admin keys are bounded.** An `admin` key limited to some agents can no longer revoke or change the quota of keys outside its agents, or of itself. When it has a quota, it cannot create or change a key above that quota (`quota_exceeds_own`, 403). To manage those keys, use an owner-wide admin key.
- **In a bridged ACP turn, fewer permission requests are approved automatically.** A request is allowed without the owner only when its title names exactly a caller-supplied tool of the relay (the other words may only be filler such as "run" or "call") and the agent itself did not classify the call as running a command or changing files. A shell command whose title merely mentions the relay and a tool name now waits for owner approval.
- **The unauthenticated portal forms** (login, sign-up, password reset) accept request bodies of at most 64 KiB.

### Install

- **Linux**: `Open-Agent-API-<version>-linux-x64.tar.gz` and `…-linux-arm64.tar.gz` bundle the official Node.js runtime and an `oaa` launcher (no desktop shell; glibc 2.28 or newer). `install.sh` (`curl -fsSL …/releases/latest/download/install.sh | sh`) needs no root: it verifies the download against the release's `SHA256SUMS`, installs under `~/.local/share/open-agent-api`, links `~/.local/bin/oaa`, and supports `--version`, `--prefix` and `--uninstall`. A download that is cut short runs nothing.
- **Docker**: a multi-stage `Dockerfile` (`node:24-slim`, a non-root user, state in the `/data` volume, a health check on `/healthz`) and `docker-compose.yml`, which publishes the port only on the host's `127.0.0.1:8787`. The first start initializes the data directory and publishes the offline sample agent. Publishing a release pushes `ghcr.io/jiangxingfan1-coder/open-agent-api` for `linux/amd64` and `linux/arm64`. The container has none of the agent command lines of your host, so it fits built-in agents, ACP and A2A remote agents, and execution nodes that connect in.
- **npm tarball**: each release carries `open-agent-api-<version>.tgz`, installed with `npm install -g <URL of the file>`. The package stays `private`: it is not on the npm registry.
- **Smaller packages**: third-party source maps, tests and documentation directories, unused builds of the icon library and the sandbox programs of other platforms are left out (the macOS `.dmg` went from 123 MB to 86 MB, measured).
- **Node.js 24 and 26**: `engines` is now `>=24.18.0 <27`, and CI runs the whole suite on both lines. The runtime bundled into the installers stays 24.18.0.
- **Release workflow**: `release.yml` also builds the two Linux packages and the npm package, stamps the version into `install.sh`, and writes every file into `SHA256SUMS`. The smoke test run on each package now imports every module, makes the first calls on three protocols against the sample agent, handles an approval through the API and through `oaa approve`, checks that a second `quickstart` creates nothing, and checks that `oaa stop` leaves no process behind.
- **Fixed**: `oaa` started through a symbolic link (for example the command that `npm install -g` creates) printed nothing; the console returned HTTP 500 for its icon library when npm had hoisted the dependency (`npx`, installation into a project).

### Windows

- Commands are found through `PATH` and `PATHEXT` (`oaa init`, `quickstart`, `connect`, `doctor`, ACP presets), and the full path with its extension is recorded. npm launchers (`codex.cmd` and the like) are started with node directly; other `.cmd` and `.bat` files go through `cmd.exe /d /s /c` with every argument escaped, so `&`, `|`, `%VAR%` and quotes in caller input are passed as text. A line break in an argument for such a file is refused (`invalid_request`).
- On Windows, `oaa connect <preset>` restarts a background gateway that it started itself by first asking it to close through `POST /v1/gateway/shutdown`, as `oaa stop` does, because there a plain termination ends the process abruptly.
- An agent's whole process tree is ended with `taskkill /T /F` on cancel, timeout and shutdown. `oaa stop` first asks the gateway to close itself through the new `POST /v1/gateway/shutdown` (an owner-wide admin key, from loopback only), and terminates the process only if it is still running after ten seconds.
- The caller-tool relay uses a named pipe instead of a Unix socket. Private files (the admin key, caller keys, `server.pid`) are restricted with `icacls`, best effort. File names that Windows treats specially (reserved device names, `:`, a trailing dot or space) are refused with `invalid_path`. `oaa status` and `oaa verify` work without `ps`.
- The whole test suite now runs on `windows-latest` in CI (`windows.yml`, one process per test file); tests that only make sense on POSIX skip with a stated reason. The messages of the PowerShell launcher scripts follow the Windows display language. Details and limits (no sandbox, forced stops, unsigned packages) are in `docs/windows.md`.

### Security

- A security review of the gateway, and its fixes: the bounds on agent-limited admin keys, the tightened automatic approval in bridged ACP turns and the portal form limit are under "Behavior changes".
- Log and error redaction now also covers execution-node tokens (`oan_…`), portal session tokens (`oas_…`) and common upstream key formats (Google `AIza…`, GitHub, Slack, AWS access keys).
- New optional limit `maxStoredBytesPerSubject`: the stored bytes of one caller's files, including images stored from requests; past it, uploads fail with `storage_quota_exceeded` (413). Unset, nothing changes.
- New optional `security.profile`: `local` (the default; nothing changes) or `public`, which sets safer defaults for every setting the configuration leaves unset: `defaultKeyExecution: workspace`, an allowlist for the environment that external agents inherit, `maxStoredBytesPerSubject` of 256 MiB, and a 120-second limit to receive a request. `oaa doctor` and `oaa status` warn when the configuration looks reachable from outside while the profile is still `local`.
- New `docs/security-model.md`: who can do what, what is exposed by default, what to do before exposing a gateway, and what is not defended (among others: portal sign-up answers `email_taken` because there is no email verification, and login failure counters live in memory only). Regression checks were added for the Host and Origin checks and for static-asset paths.

### Compatibility

- **Compatibility lab** (`integrations/compat/`, `npm run compat`, and `compat.yml` in CI on every push and weekly): the official `openai`, `anthropic` and `google-genai` Python SDKs and the Node `openai`, `@anthropic-ai/sdk` and `@google/genai`, the Vercel AI SDK, LangChain, LiteLLM, the OpenAI Agents SDK and LlamaIndex run against an isolated gateway with an offline agent. The requests of Open WebUI, LibreChat, Chatbox, Cherry Studio, LobeChat, NextChat, Dify, n8n, Continue, Cline, Roo Code, Zed and Cursor, read from their source or documentation, are replayed. Which client was run, which was replayed and which is unverified, with versions and configuration, is in `docs/compatibility.md`.
- Changes made because of what the lab found: sampling and vendor parameters are tolerated (see "Behavior changes"); `reasoning_effort` and `reasoning.effort` are routing hints; Responses accepts `instructions`, typed message items and `output_text` history; `GET /v1/models/{id}` answers in the OpenAI, Claude and Gemini shapes; a zero-length JSON body on `POST` (what the official SDKs send for `responses.cancel`) is no longer `invalid_json`; the answer to a CORS preflight lists the headers the browser asked for; Gemini bodies may use snake_case field names (`google-genai` 3.3 used to lose its tool parameters), and `/v1beta/{agent}:generateContent` without `models/` is accepted; a trailing or doubled slash in the Base URL still routes, and a 404 for a missing or duplicated `/v1` says so.

### New capabilities

- **Structured output** (`structured-output-v1`): the contract described under "Behavior changes", on all four wire formats, with schema checks when the request arrives (`invalid_schema`, `schema_dialect_unsupported`, `output_schema_unsupported`) and correction rounds for kernel agents and for external agents whose session can be continued. The task inspector shows the contract and the corrections used. The schema is not passed to the model provider's own structured-output feature. See `docs/structured-output.md`.
- **Image input** (`image-input-v1`): PNG, JPEG, GIF and WebP, through OpenAI Chat and Responses, Claude Messages, Gemini, UAP and the native body, inline, as an uploaded file, or as an `https` URL. The limits are 5 MiB per image, 10 images and 8 MiB per request (`images.*`). An image is stored as an input file of the caller. Each agent receives it in the form it can use, or the request is refused before a run exists; `GET /v1/models` shows `image_input`. The gateway does not fetch remote URLs by default. New errors: `image_invalid`, `image_too_large`, `too_many_images`, `image_fetch_failed`, `image_delivery_failed`. See `docs/images.md`.
- **Run-event webhooks** (`webhooks-v1`): signed (HMAC-SHA256) HTTPS callbacks for `run.requires_action`, `run.completed`, `run.failed`, `run.cancelled`, `run.incomplete` and `run.interrupted`, with a durable queue, six attempts over roughly 40 minutes, endpoint and delivery management under `/v1/webhooks`, outbound address checks (stricter under `security.profile: "public"`), and a read-only list in the console. `examples/webhook-receiver.mjs` is a receiver that can approve pending items. Only owner-wide admin keys configure endpoints. See `docs/webhooks.md`.

- **Model provider presets**: `oaa connect <preset>` gives the built-in agent a model with one command and publishes `agent/assistant`, a general assistant with the workspace file tools. Presets: `ollama`, `lmstudio`, `openai-compatible`, `openai`, `anthropic`, `gemini-api`, `openrouter`, `deepseek`, `moonshot`, `zhipu`, `siliconflow`, `groq`, `together` and `mistral`. A provider can now take its key from a file (`apiKeyFile`, read on every call, so rotating the key needs no restart) or need no key (`noApiKey`, for local models), and has the new settings `streamUsage` and `preset`. A key is never accepted on the command line. A failing upstream call now names the provider and what to change, with the new codes `upstream_auth_failed`, `upstream_model_not_found` and `upstream_incompatible`. The console's publish dialog for a built-in agent lets you pick from the configured providers, and the agent cards show the provider in use and whether its key resolves. The preset values were taken from each service's documentation. See `docs/models.md`.
- **Stream progress** (`stream-progress-v1`): the behavior described under "Behavior changes", chosen per request (`X-OAA-Progress`, `oaa.progress`) or per protocol (`streamProgress`). The lines never carry tool arguments, tool results, prompts or internal identifiers, and follow `Accept-Language`. The compatibility lab runs a `stream_progress` scenario for each SDK and framework; of the chat clients only Dify was checked against its source, and it would put the progress into the answer on Chat, which is why Chat stays off. See `docs/progress.md`.

### Developer platform

- A listing can turn on `host_execution`, so that platform accounts may call that one external agent (Codex, Claude Code, ACP agents, adapters, kernel agents with host tools). It is off by default and audited, and an agent it delegates to needs its own switch. The console's listing dialog has the switch with its explanation, and the listing table shows which agents accounts cannot call yet. See `docs/platform.md`.
- Billing: the per-task price is held at the start and released when a task does not complete, token charges no longer overdraw, and an agent that reports no usage can only be priced per task (see "Behavior changes").
- `examples/platform-walkthrough.ts` runs the whole path offline with the sample agent: list, switch on, credit code, sign up, key, call, charge, top up.

### Command line

- New `oaa approvals` (with `--watch`), `oaa approve` and `oaa deny`: list and decide approvals from a terminal. The operation is printed before it is decided.
- New `oaa status`: one read-only answer to how the gateway and its agents are doing, with `--json`.
- New `oaa verify AGENT`: prints a plan, and with `--confirm-live-cost` runs the real-agent acceptance scenarios on an isolated gateway and writes a scrubbed `report.md` and `report.json` that can be attached to an issue (template: "Agent verification report"). `examples/live-agents-acceptance.ts` now shares its scenarios.
- New `oaa webhook add|list|remove|test|deliveries`.
- New `oaa connect <preset>` and `oaa models`: connect a model provider to the built-in agent, and list the configured providers with whether their keys resolve and whether their endpoints answer (loopback ones automatically, hosted ones only with `--check`, which asks for the model list and nothing else). `oaa connect` never calls a model unless you add `--test`, and then only for a loopback endpoint.
- New `oaa prune [--older-than 30d] [--dry-run] [--vacuum]`: delete finished runs older than a cutoff, with their events and files (see "Stability"). `oaa doctor` now reports the database size.
- The command reference is `docs/cli.md`.

### Stability

The new `docs/stability.md` has the method, the numbers, the crash-recovery semantics and the limits.

- **Data retention.** Nothing is deleted unless you ask. The new `retention` setting (`runsDays`, `intervalMinutes`, `warnDatabaseMb`) prunes finished runs older than `runsDays` on a timer, and `oaa prune` (`--older-than`, `--dry-run`, `--vacuum`) or `POST /v1/maintenance/prune` (an owner-wide admin key) does it once. Runs that are queued, running, waiting for approval or interrupted are never pruned. Account and billing records (the ledger, key usage totals) and memories are not pruned either. `oaa doctor` reports the database size, and `oaa status` prints a note above `retention.warnDatabaseMb` (1024 MB by default); neither deletes anything.
- **Memory and database growth found by a soak test, and fixed.** (1) Every execution armed an uncancellable 30-minute timeout, which kept each finished run's data reachable for 30 minutes (the heap grew by about 1.3 MB/min under load); it is now a timer that is cleared. (2) Timers that were re-armed with exact durations each left one empty internal Node timer list; Node frees such a list only once the original duration has passed, so this was a backlog that grows with load and with the length of the deadlines, not a permanent leak, and those timers now use rounded durations. (3) After a prune, the console's activity window kept the runs that had just been deleted. (4) An endpoint that kept failing let its delivery queue grow without a bound. Before these fixes a 65-minute run grew the heap by 0.29 MB/min and the database by 0.8 MB/min; after them, by 0.008 and 0.0 MB/min.
- **Event callbacks:** at most 10,000 deliveries wait per endpoint; the oldest beyond that are marked `failed` with `queue_overflow`.
- **Backups and logs:** the backup written before a migration is kept only for the newest 3 per source version (it was unbounded, so a supervisor restarting a failing gateway in a loop could fill the disk), and `server.log` of a background gateway is rotated to `server.log.1` at start when it is larger than 10 MB. A session workspace that a prune deleted is rebuilt by the local worker instead of being reused from its cache.
- **`npm run soak`** (macOS and Linux only; not part of `npm test`) runs a real gateway process against a fake model and the offline sample agent under a mixed load, restarts it three times (SIGTERM, SIGKILL, SIGTERM), and checks recovery and a set of pass criteria. Its latest result, on macOS (Apple silicon), Node 24, concurrency 8, on the code of this version: a 32-minute run with the restarts (34,010 requests without an unexpected error; 24 more failed inside the restart windows, which are counted separately) and a 62-minute run in one segment (67,799 requests, no unexpected error). Both met every criterion: the database and the file descriptors, handles and child processes stayed flat, the runs that were in progress at the SIGKILL were `interrupted` after the restart, and no agent process outlived the gateway. The criterion for the memory of a short last segment was revised after the 32-minute run, whose 10-minute last segment had a fitted slope that mostly measured ordinary swings of about ±25 MB; the 32-minute run met the criterion as revised, not as first written (`docs/stability.md` has the details).
- **`npm run upgrade-check`** repeats an upgrade with real binaries: an older release creates data, the current build serves it, and the older release opens it again. A real 0.0.64 database is a test fixture.

Everything else about the desktop apps is not verified; see "Not yet verified".

### Not yet verified

- **Real agents.** End-to-end verification with a real agent was done once, with Antigravity on 2026-11-13, using an earlier version of the acceptance script. Codex and Claude Code have not been run through it; `oaa verify` is the way for anyone with one of them installed to do so.
- **Image delivery to Codex and Claude Code** is implemented from the vendors' documentation and has not been run against the real agents. Whether the Claude Agent SDK ends a session normally after the single streamed message that carries an image is an open question. Antigravity and DSH receive images as workspace files, also not run against the real agents.
- **Structured-output correction rounds with real external agents**, and caller-tool bridging beyond the manual session of 2026-11-11 (Antigravity and Qoder), are tested with stand-in agents only.
- **Webhook delivery to a real public HTTPS endpoint**: the tests use local plain-http receivers.
- **The desktop apps, beyond those five checks.** Not verified: the three messages for a port that is in use; switching the system language between Chinese and English in both directions (only the owner's current language was seen); that a second start with the same data folder no longer shows the first-launch note; recognizing and reusing a gateway that outlived a crashed app; the Intel package; the normal, non-isolated installation (default data folder, port 8787) of this version; and the bilingual messages of the Windows launcher (there is no Windows machine for it, and CI only checks the PowerShell syntax). The logic behind the macOS app is covered by offline tests.
- **Windows with real agents.** CI passes the full suite on Windows with stand-in agents.
- **The release workflow with its new parts.** The Linux packages, `install.sh`, the npm tarball, the extended smoke test and the multi-architecture Docker push have not yet run on GitHub: the first run is the release of this version, and so is the first run of the Windows package of this version. The Docker image has been built (amd64) and smoke-tested in CI.
- **The compatibility lab uses a deterministic fixture model and the sample agent**, never a real agent. A replay shows that the gateway accepts a client's recorded request and answers in a form it parses, not that the whole application works. Cursor is unverified, and LibreChat and LobeChat are only partly derived from source.
- **Developer platform**: the success path of billing with a real external agent, and a public deployment, have not been seen.
- **Model provider presets** have not been run against any real model service. The addresses and differences come from each service's documentation, and the tests use fake services. If a preset stops working, `oaa models --check` and the error code say which setting to change.
- **The documentation site** has been built and its links checked, but not seen on real GitHub Pages: the first deployment is its first look.
- **The soak** used a fake model and the offline sample agent only, and ran for at most 62 minutes. Real providers and real agent command lines add latency, memory and failure modes it does not measure, and caches with designed bounds fill over hours. In one earlier 32-minute attempt the gateway needed about 110 seconds to answer after a SIGKILL; it did not recur in three further SIGKILL restarts or in a manual try, and the cause is not known (`docs/stability.md`, "Known limits").
- **Stream progress for external agents** is tested with stand-ins, not with the real agents.
- **Not done**: passing a schema to the model provider's own structured-output feature, forced tool choice, and a real payment channel.

## 0.0.64 (2026-11-14)

Public versions are renumbered from 0.0.64. The 0.1.0 to 0.6.4 entries in the Chinese changelog are internal version numbers from before the public release, kept as a record.

The first public version: open source under Apache-2.0, with macOS (Apple silicon and Intel) and Windows installers that bundle their own Node runtime. Gateway behavior is the same as 0.6.4.

### Release builds

- The packaging script has a new release mode, `--release`: it installs nothing into any application directory, links no CLI, and writes nothing to the user's home directory; artifacts are written only to `release/` (a write outside it is an outright error). `--dry-run` only prints the paths each step would write and the external commands it would run. Local development packaging (without `--release`) behaves as before. New scripts: `npm run package:release:mac` and `package:release:win`.
- Release packages bundle the official Node runtime (`--node-dir`, with the version checked against `engines.node`), and, following `package-lock.json`, exclude development dependencies, the proprietary `@anthropic-ai/claude-agent-sdk` and the packages only it references, and native packages for other platforms and architectures. macOS supports `--arch arm64|x64`; artifacts are named uniformly `Open-Agent-API-<version>-macOS-<arch>.dmg` and `…-win-x64.zip`, and a `SHA256SUMS` is generated.
- When the Claude Agent SDK is missing, the Claude native engine returns `adapter_unavailable` with installation instructions (it can be installed separately into `~/.oaa/vendor` or `OAA_CLAUDE_SDK_DIR`), and `oaa doctor` and the local backend information mark it `requires_separate_install`; when the SDK is installed with the dependencies, behavior is unchanged.
- Windows launcher: the Node version hint now matches `engines`; fixed `oaa.cmd` expanding `%ERRORLEVEL%` too early inside a parenthesized block, which gave a wrong exit code; the desktop launcher now loads the previously missing `System.Windows.Forms` (before, a failure showed no message at all), reads the port from the configuration, and on a busy port or a failed start shows a message and the log location; a new `Stop-OpenAgentAPI.cmd` quits the background gateway; the `.ps1` files are written with a UTF-8 BOM so Chinese text displays correctly.
- A new GitHub Actions release workflow, `release.yml` (triggered by pushing a `v*` tag or manually): on each of the three platforms it checks, downloads the official Node and verifies it with `SHASUMS256.txt`, packages, and smoke-tests (running the CLI with the Node inside the package, and starting the gateway on a random loopback port to check the `/healthz` version), and finally creates a draft Release. `ci.yml` is extended to Ubuntu, macOS and Windows. See `docs/releasing.md`.

### Getting started

- Walked through the README in full on a clean HOME, on both the source route and the installer route (using the ACP test stand-in in the repository in place of an external agent), and corrected the getting-started steps accordingly: first say that you need an agent to publish; use `serve --detach` by default; add creating a key on the command line, fetching the result with `wait` after `invoke`, a table of common errors, and the steps to walk the whole path with the test stand-in when no agent is installed.
- New `oaa quickstart`: initialize (skipped if already done), start the gateway in the background listening only on 127.0.0.1 (reused if already running, restarted if the configuration changed; on a busy port it reports `port_in_use` and suggests `--port`), publish the offline sample agent `agent/sample`, generate a caller key (a private file, reused if one exists and is valid), make one real call and print the answer, the Base URL, the model, a curl command, OpenAI SDK code, and the next step to connect a local codex / claude / agy or a built-in agent. Running it again does not create anything twice. Output is bilingual, Chinese and English.
- New `oaa connect <codex|claude|agy|ACP preset name>`: detect whether it is installed, enable it on this gateway, publish it as `agent/<name>` (skipped if already published), confirm that the quickstart key can call it (otherwise create a separate key that can call only it), and print the model and a curl command. It does not call the agent, and it explains that the first call uses the agent's own login and quota. The end of quickstart now prints one `oaa connect …` line for each detected agent.
- The Windows desktop launcher now starts the gateway with `oaa quickstart --dir %LOCALAPPDATA%\OpenAgentAPI`, so a callable offline sample agent exists from the first launch, with the output written to `quickstart.log`; the stop script also handles `oaa stop`. `README-WINDOWS.txt` makes `oaa.cmd quickstart` the first step.
- Console: when publishing returns the `not_runnable_here` warning, the publish dialog stays open and shows the reason; when the sample agent `agent/sample` already exists, the first step of the overview's getting-started checklist counts as done.
- The sample agent's tool demo now reads the local time instead of counting prompt characters (that number included context the gateway adds, which was easy to misread).
- New offline sample agent `examples/sample-agent.mjs` (ACP; it calls no model and uses no network, and its answer says it is a sample), demonstrating several steps, one tool call, and one optional approval; it is defined in `examples/sample-agent.json`. It ships with the source and the installers.
- Error messages made more accurate: `model_unavailable` names the engine or adapter that is not installed or not enabled, the provider environment variable that is missing, and how to fix it; publishing an agent that cannot run on this machine right now succeeds but returns a `warning` (`not_runnable_here`); when a restricted key requests an unauthorized or non-existent `model`, the message suggests `GET /v1/models` (without revealing whether it exists), and an admin key's `agent_not_found` gets the same hint; the 401 message says where the key comes from. The error body shapes of the four entries are unchanged.
- `oaa init` prints the location of the admin key file and the next step (`oaa quickstart`).
- macOS desktop app: on first launch it publishes the offline sample agent (the marker file is upgraded to `.seeded-v2`, so existing users get it too); the agy sample is published only when agy is detected; the publishing of the non-existent `examples/smart-repo-inspector.oaa` is removed. The behavior of automatically enabling the detected local agents is unchanged, and the documentation now describes it truthfully.
- The `examples/` in the installers no longer carries the `.ts` files that cannot run, `live-agents/` and `gemini-sdk-probe.mjs`; when npm cannot be found, the Claude SDK install hint first says that Node.js (which includes npm) must be installed separately.
- New `oaa key create`: generates a caller key through `POST /v1/keys`, writes it to a private file with mode 0600 (by default `.oaa/keys/<name>.key`, never overwriting an existing file), and prints only the file path, the Base URL, the model name and a ready-to-run curl command, never the key itself.
- New `oaa stop`: stops the gateway started by `oaa serve --detach`, sending SIGTERM only to the pid that `/health` reports.
- When the command line cannot reach the gateway it reports `gateway_unreachable` with a hint on how to start it (before, it was `execution_failed: fetch failed`); an unknown option reports `arguments` (before, `execution_failed`); `token_required` gains a next-step suggestion.

### Preparing for open source

- English support: every error code in the error catalog gains an English description `en` and a next-step suggestion `nextEn` (returned by `GET /v1/errors` as well); HTTP error responses choose their language by `Accept-Language`, and without that header use the process default language (`OAA_LOCALE`, otherwise the system locale). Throw sites that had only Chinese text (ACP agents, local backends, the Claude SDK install hint and so on) are now bilingual, and the error body shapes of the four entries are unchanged. The help of `oaa` is now grouped and shown in Chinese or English by the process default language, and on failure it appends the next-step suggestion from the catalog. The default experience on Chinese systems is unchanged; tests are all fixed to Chinese. The rules are in `docs/protocol.md`, "Language of error messages".
- The descriptions of ACP presets (`presets[].notes` of `GET /v1/local/backends`, shown on the console's local backends page) come in Chinese and English versions and are chosen by `Accept-Language` in the same way, with the process default language when the header is absent; the English text is in `src/config/agent-presets-en.ts`.
- Added `LICENSE` (the standard full text of the Apache License 2.0) and `NOTICE` (the copyright holder is The Open Agent API Authors, and the Open Design Apache-2.0 attribution is kept). `package.json` declares `"license": "Apache-2.0"` and gains `repository`, `bugs`, `homepage` and a `files` allowlist (only `dist/src`, `web`, and documentation and license files); `"private": true` is kept.
- `THIRD_PARTY_NOTICES.md` now includes the attribution for `@anthropic-ai/sandbox-runtime` (Apache-2.0), lists all runtime dependencies with their licenses, and lists the proprietary `@anthropic-ai/claude-agent-sdk` separately (installed by users themselves and not covered by this project's license); it carries the license review of the runtime dependency closure, and the full license text of `lucide` is copied to `licenses/Lucide-ISC.txt`.
- Added `CONTRIBUTING.md`, `SECURITY.md` (vulnerabilities are reported through GitHub's private vulnerability reporting) and `CODE_OF_CONDUCT.md`, plus issue and pull request templates.
- The top of the README gains links to the license and the community files, and the "Licenses and attribution" section is expanded; the getting-started steps were checked against `package.json` and `src/cli.ts`, and every command and argument exists.
- Example domains in test fixtures that carried a personal name were changed to `agents.example.com`.
