## 0.0.64 (2026-11-14)

Public versions are renumbered from 0.0.64. The 0.1.0 to 0.6.4 entries in the Chinese changelog are internal version numbers from before the public release, kept as a record.

The first public version: open source under Apache-2.0, with macOS (Apple silicon and Intel) and Windows installers that bundle their own Node runtime. Gateway behavior is the same as 0.6.4.

### Release builds

- The packaging script has a new release mode, `--release`: it installs nothing into any application directory, links no CLI, and writes nothing to the user's home directory; artifacts are written only to `release/` (a write outside it is an outright error). `--dry-run` only prints the paths each step would write and the external commands it would run. Local development packaging (without `--release`) behaves as before. New scripts: `npm run package:release:mac` and `package:release:win`.
- Release packages bundle the official Node runtime (`--node-dir`, with the version checked against `engines.node`), and, following `package-lock.json`, exclude development dependencies, the proprietary `@anthropic-ai/claude-agent-sdk` and the packages only it references, and native packages for other platforms and architectures. macOS supports `--arch arm64|x64`; artifacts are named uniformly `Open-Agent-API-<version>-macOS-<arch>.dmg` and `…-win-x64.zip`, and a `SHA256SUMS` is generated.
- When the Claude Agent SDK is missing, the Claude native engine returns `adapter_unavailable` with installation instructions (it can be installed separately into `~/.oaa/vendor` or `OAA_CLAUDE_SDK_DIR`), and `oaa doctor` and the local backend information mark it `requires_separate_install`; when the SDK is installed with the dependencies, behavior is unchanged.
- Windows launcher: the Node version hint now matches `engines`; fixed `oaa.cmd` expanding `%ERRORLEVEL%` too early inside a parenthesized block, which gave a wrong exit code; the desktop launcher now loads the previously missing `System.Windows.Forms` (before, a failure showed no message at all), reads the port from the configuration, and on a busy port or a failed start shows a message and the log location; a new `Stop-OpenAgentAPI.cmd` quits the background gateway; the `.ps1` files are written with a UTF-8 BOM so Chinese text displays correctly.
- A new GitHub Actions release workflow, `release.yml` (triggered by pushing a `v*` tag or manually): on each of the three platforms it checks, downloads the official Node and verifies it with `SHASUMS256.txt`, packages, and smoke-tests (running the CLI with the Node inside the package, and starting the gateway on a random loopback port to check the `/healthz` version), and finally creates a draft Release. `ci.yml` is extended to Ubuntu, macOS and Windows. See `docs/releasing.md`.

### Getting started

- Walked through the README in full on a clean HOME, on both the source route and the installer route (using the ACP test stand-in in the repository in place of an external agent), and corrected the getting-started steps accordingly: first say that you need an agent to publish; use `serve --detach` by default; add creating a key on the command line, fetching the result with `wait` after `invoke`, a table of common errors, and the steps to walk the whole path with the test stand-in when no agent is installed.
- New `oaa quickstart`: initialize (skipped if already done), start the gateway in the background listening only on 127.0.0.1 (reused if already running, restarted if the configuration changed; on a busy port it reports `port_in_use` and suggests `--port`), publish the offline sample agent `agent/sample`, generate a caller key (a private file, reused if one exists and is valid), make one real call and print the answer, the Base URL, the model, a curl command, OpenAI SDK code, and the next step to connect a local codex / claude / agy or a built-in agent. Running it again does not create anything twice. Output is bilingual, Chinese and English.
- New `oaa connect <codex|claude|agy|ACP preset name>`: detect whether it is installed, enable it on this gateway, publish it as `agent/<name>` (skipped if already published), confirm that the quickstart key can call it (otherwise create a separate key that can call only it), and print the model and a curl command. It does not call the agent, and it explains that the first call uses the agent's own login and quota. The end of quickstart now prints one `oaa connect …` line for each detected agent.
- The Windows desktop launcher now starts the gateway with `oaa quickstart --dir %LOCALAPPDATA%\OpenAgentAPI`, so a callable offline sample agent exists from the first launch, with the output written to `quickstart.log`; the stop script also handles `oaa stop`. `README-WINDOWS.txt` makes `oaa.cmd quickstart` the first step.
- Console: when publishing returns the `not_runnable_here` warning, the publish dialog stays open and shows the reason; when the sample agent `agent/sample` already exists, the first step of the overview's getting-started checklist counts as done.
- The sample agent's tool demo now reads the local time instead of counting prompt characters (that number included context the gateway adds, which was easy to misread).
- New offline sample agent `examples/sample-agent.mjs` (ACP; it calls no model and uses no network, and its answer says it is a sample), demonstrating several steps, one tool call, and one optional approval; it is defined in `examples/sample-agent.json`. It ships with the source and the installers.
- Error messages made more accurate: `model_unavailable` names the engine or adapter that is not installed or not enabled, the provider environment variable that is missing, and how to fix it; publishing an agent that cannot run on this machine right now succeeds but returns a `warning` (`not_runnable_here`); when a restricted key requests an unauthorized or non-existent `model`, the message suggests `GET /v1/models` (without revealing whether it exists), and an admin key's `agent_not_found` gets the same hint; the 401 message says where the key comes from. The error body shapes of the four entries are unchanged.
- `oaa init` prints the location of the admin key file and the next step (`oaa quickstart`).
- macOS desktop app: on first launch it publishes the offline sample agent (the marker file is upgraded to `.seeded-v2`, so existing users get it too); the agy sample is published only when agy is detected; the publishing of the non-existent `examples/smart-repo-inspector.oaa` is removed. The behavior of automatically enabling the detected local agents is unchanged, and the documentation now describes it truthfully.
- The `examples/` in the installers no longer carries the `.ts` files that cannot run, `live-agents/` and `gemini-sdk-probe.mjs`; when npm cannot be found, the Claude SDK install hint first says that Node.js (which includes npm) must be installed separately.
- New `oaa key create`: generates a caller key through `POST /v1/keys`, writes it to a private file with mode 0600 (by default `.oaa/keys/<name>.key`, never overwriting an existing file), and prints only the file path, the Base URL, the model name and a ready-to-run curl command, never the key itself.
- New `oaa stop`: stops the gateway started by `oaa serve --detach`, sending SIGTERM only to the pid that `/health` reports.
- When the command line cannot reach the gateway it reports `gateway_unreachable` with a hint on how to start it (before, it was `execution_failed: fetch failed`); an unknown option reports `arguments` (before, `execution_failed`); `token_required` gains a next-step suggestion.

### Preparing for open source

- English support: every error code in the error catalog gains an English description `en` and a next-step suggestion `nextEn` (returned by `GET /v1/errors` as well); HTTP error responses choose their language by `Accept-Language`, and without that header use the process default language (`OAA_LOCALE`, otherwise the system locale). Throw sites that had only Chinese text (ACP agents, local backends, the Claude SDK install hint and so on) are now bilingual, and the error body shapes of the four entries are unchanged. The help of `oaa` is now grouped and shown in Chinese or English by the process default language, and on failure it appends the next-step suggestion from the catalog. The default experience on Chinese systems is unchanged; tests are all fixed to Chinese. The rules are in `docs/protocol.md`, "Language of error messages".
- The descriptions of ACP presets (`presets[].notes` of `GET /v1/local/backends`, shown on the console's local backends page) come in Chinese and English versions and are chosen by `Accept-Language` in the same way, with the process default language when the header is absent; the English text is in `src/config/agent-presets-en.ts`.
- Added `LICENSE` (the standard full text of the Apache License 2.0) and `NOTICE` (the copyright holder is The Open Agent API Authors, and the Open Design Apache-2.0 attribution is kept). `package.json` declares `"license": "Apache-2.0"` and gains `repository`, `bugs`, `homepage` and a `files` allowlist (only `dist/src`, `web`, and documentation and license files); `"private": true` is kept.
- `THIRD_PARTY_NOTICES.md` now includes the attribution for `@anthropic-ai/sandbox-runtime` (Apache-2.0), lists all runtime dependencies with their licenses, and lists the proprietary `@anthropic-ai/claude-agent-sdk` separately (installed by users themselves and not covered by this project's license); it carries the license review of the runtime dependency closure, and the full license text of `lucide` is copied to `licenses/Lucide-ISC.txt`.
- Added `CONTRIBUTING.md`, `SECURITY.md` (vulnerabilities are reported through GitHub's private vulnerability reporting) and `CODE_OF_CONDUCT.md`, plus issue and pull request templates.
- The top of the README gains links to the license and the community files, and the "Licenses and attribution" section is expanded; the getting-started steps were checked against `package.json` and `src/cli.ts`, and every command and argument exists.
- Example domains in test fixtures that carried a personal name were changed to `agents.example.com`.
