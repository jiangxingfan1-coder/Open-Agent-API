# Security policy

English · [简体中文](SECURITY.zh-CN.md)

## Supported versions

Open Agent API is currently in the 0.x stage, and security fixes are provided only for the **latest released version**. Please upgrade to the latest version first and confirm that the problem still exists.

## Reporting a vulnerability

Please **do not** disclose a vulnerability in a public issue, discussion or pull request. Use GitHub's private vulnerability reporting (Security Advisories): open the "Security" tab of this repository and choose "Report a vulnerability". Reports in English or Chinese are both welcome.

Please include in the report, as far as you can:

- the affected version (`version` in `package.json`) and the environment (Node version, operating system);
- a description of the problem, its impact, and minimal steps to reproduce it;
- the fix you think would work (optional).

Please note:

- **Do not post keys, tokens, the contents of `.oaa/admin.token`, or directly exploitable details in any public place**; if your logs contain them, redact them first.
- Do not test services you do not own or are not authorized to test, and do not access or modify other people's data.
- We will do our best to confirm and handle reports, but this is a community-maintained open source project and does not promise a fixed response time. Please do not make the details public before a fix is released.

## The project's security boundary

Only behavior that has been verified in the code is listed below, to help judge whether an issue is a vulnerability.

- **Listens on this machine only by default**: the gateway listens on `127.0.0.1`, port 8787, by default (`src/config/config.ts`). `allowedHosts` allows only `127.0.0.1`, `localhost` and `[::1]` by default; `trustProxy` is off by default. Opening it to the local network or the public internet is an explicit choice of whoever deploys it; before deploying, read [docs/deploy-public.md](docs/deploy-public.md).
- **Cross-origin access**: cross-origin browser requests are allowed only from the same origin, or from the origins listed in `allowedOrigins`.
- **Keys**: for API keys created in the console, the database stores only a SHA-256 digest, and the plaintext is returned only once, at creation; execution node credentials are likewise stored as digests only. The `.oaa/admin.token` generated by `oaa init` is a file written with owner-only read and write permissions (0600) and is never printed in the terminal; do not share it. Passwords of developer platform accounts are stored with scrypt and a salt.
- **Key tiers**: keys have scopes (`invoke`, `read`, `files`, `approve`, `admin`, `billing`) and a range of agents they may call, and a key you create cannot exceed the creator's own permissions.
- **External agents inherit permissions**: external agents such as Codex, Claude Code and ACP agents run with the permissions the host runtime allows, and this gateway does not sandbox them by default (for the optional execution levels and the sandbox, see `docs/protocol.md` and `docs/sandbox-design.md`). This is **not** an isolation boundary against malicious nodes, scripts or local processes of the same user; publish and enable only agents you trust, and configure approvals for them.
- **External agents are disabled by default**: a discovered external agent has to be enabled explicitly by an admin in the console.

If you find that any of the above does not match actual behavior, that is exactly the kind of problem worth reporting.
